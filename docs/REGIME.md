# 市场周期 / 情绪周期 — 判定规则速查

这一页（前端 `Regime.tsx`，「市场环境」+「情绪周期」两个 tab）背后是**两套完全独立的判定引擎**，
互不干扰。想调整任何一部分，改完只需在页面上点「重算」（全量回填历史）。

| 引擎 | 输出 | 问的问题 | 核心文件 |
| :--- | :--- | :--- | :--- |
| 市场环境 state | 强势 / 偏强 / 震荡 / 偏弱 / 弱势 | 今天整体赚钱难不难？ | `backend/app/services/regime_builder.py` |
| 情绪周期 phase | 冰点 / 启动 / 主升 / 高潮 / 退潮 / 修复 | 涨停梯队处在周期哪个位置？ | `backend/app/services/market_phase.py` |
| 主线 mainline | 概念 / 行业排行 | 谁在带队？ | `backend/app/services/market_mainline.py` |

## 一、市场环境：五档状态

四个子维度各自归一化到 0–100，再按权重加权成综合分，最后按阈值切档。

**权重**（`regime_builder.py` 第 32–37 行）

```
赚钱 profit        0.35
投机 speculation   0.25
抗跌 resilience    0.20
趋势 trend         0.20
```

**归一化**（第 65–115 行）。`_score(v, low, high)` 是把 v 在 [low, high] 区间线性映射到 0–100 并钳制边界。
所有 low/high 都是 **A 股 2022–2026 真实数据的 p15/p85 分位数**，所以常态落在中间、不会两极化。

| 维度 | 构成 | 区间 (p15→p85) | 内部权重 |
| :--- | :--- | :--- | :--- |
| 赚钱 | 涨家数占比 | 21 → 75 | 45% |
| | 均涨幅 | −1.2 → 1.3 | 25% |
| | 中位涨幅 | −1.2 → 1.3 | 20% |
| | 强弱差 | −13 → 14 | 10% |
| 投机 | 封板率 | 57 → 75 | 40% |
| | 涨停数 | 35 → 97 | 30% |
| | 连板高度 | 4 → 9 | 30% |
| 抗跌 | 大跌股占比(**反向**, `100 − score`) | 2 → 18 | 100% |
| 趋势 | 指数涨幅 | −2.5 → 2.5 | 50% |
| | MA20 上方占比 | 22 → 76 | 50% |

> 「抗跌」是四维里唯一单变量且反向的：大跌日大跌股占比 >18% → 子分趋 0，
> 光这一项就能把综合分拽进弱势。这是刻意设计，用来识别系统性杀跌。

**状态阈值**（第 39–44 行）

```
score >= 70  强势
       >= 55 偏强
       >= 45 震荡
       >= 30 偏弱
       <  30 弱势
```

## 二、情绪周期：六阶段

不看指数，只看**连板梯队**。全部从已存储的 `consecutive_limit_ups` 派生，2020-08 起可全历史回算。

### 处理流水线

1. **聚合原始量**：最高连板高度 `height` / 首板家数 `first_board` / 2板以上家数 `ge2` /
   晋级率 `promo_rate` / 封板率 `seal_rate`。
2. **晋级率定义**：昨日连板池今日继续封板的比例；**池子 < 10 家记 null**（小样本噪声）。
3. **EMA 平滑**：α = 1/3（约 5 日），五个驱动各自平滑；promo 先前向填充。
4. **逐日规则判定**：按固定优先级自上而下匹配，命中即返回。
5. **后处理 A — 持续性**：与当前标签不同的新标签，需**连续 2 天**才真正切换，防止单日抖动。
6. **后处理 B — 大盘否决**：若当日五档 state 属于 `weak` / `lean_weak`，
   则 `高潮 / 主升 / 启动` 一律强制降级为 `修复`。

### 阈值表（`market_phase.py` 第 48–86 行，全部常量集中在那里）

判定顺序 = 优先级，**命中即返回**。

| 优先级 | 阶段 | 条件（均用 EMA 平滑值） |
| :--- | :--- | :--- |
| 1 | **高潮** climax | `ge2 ≥ 50` 或 `first_board ≥ 220` |
| 2 | **主升** rally | (`h ≥ 7` 且 `ge2 ≥ 15` 且 `promo ≥ 0.23`)<br>或 (`promo ≥ 0.30` 且 `ge2 ≥ 12` 且 `h ≥ 5`) |
| 3 | **冰点** ice | `h ≤ 4` 且 `ge2 ≤ 6` 且 `first_board ≤ 24` |
| 4 | **退潮** ebb | 自高位回落(5日前 `ge2 ≥ 12` 或 `h ≥ 6`) 且 (`promo ≤ 0.15` 且 `ge2` 低于5日前)<br>或 (`promo ≤ 0.13` 且 `seal ≤ 0.57`) |
| 5 | **启动** ignite | (`ge2 − ge2₋₅ ≥ 3` 且 `ge2 ≥ 8` 且 `promo ≥ 0.20`)<br>或 (`h − h₋₅ ≥ 1` 且 `h ≥ 5` 且 `promo ≥ 0.19`) |
| 6 | **修复** repair | 兜底，以上皆不命中 |

**两个容易看漏但很关键的设计**（改之前务必理解）：

- **冰点排在退潮前面**是刻意的。注释原文：退潮的规则 B 不带「自高位」条件，
  顺序反了会把长期冰点误标成退潮。
- **大盘否决**是为了防止 2024-01 那种「微盘在崩、中字头涨停生态却很好」的背离。

### 阈值标定来源

2020-08 ~ 2026-08 全市场 **1454 个交易日**的 p10/p60/p90 分位数。
关键异常段（2024-09/10 rally→climax→ebb、2024-01/02 微盘退潮）人工核过归属。
标定脚本一次性运行、未提交仓库。

## 三、主线 mainline（`market_mainline.py`）

**评分权重**（第 40–44 行）

```
概念内涨停家数 limit_up_count  0.35
最高连板 max_boards           0.25
梯队档位数 rungs_filled       0.25
2板以上家数 ge2_count         0.15
```

**过滤默认值**

| 参数 | 默认 | 说明 |
| :--- | :--- | :--- |
| `min_members` | 4 | 成员数下限 |
| `max_members` | 600 | 上限，用来滤掉宽基/风格标签（融资融券 ~7700 家、沪深股通 ~3300 家） |
| `blacklist` | 空 | 按名称屏蔽，不论大小 |
| `exclude_st` | true | 剔除 ST（状态桶不是题材，主板 5% 便宜板时代曾系统性霸榜） |
| `_MIN_LIMIT_UP` | 3 | 单概念当日最少涨停家数，低于此不参与排名 |

这些**在页面上「过滤」面板里就能改**，存进 preferences，改完自动重算，不需要动代码。

> 已知口径限制：概念成分用的是**当前快照回看历史**，早年存在归属漂移（`MEMBERSHIP_NOTE` 里有说明）。

## 四、改完之后怎么生效

- 改了 `market_phase.py` 阈值 → 页面上点右上角「重算」 → `POST /api/regime/recompute`
  → `run_regime_batch` 全量重算 → `refresh_phase_labels` 重标阶段 → 回填主线（概念+行业）。
- 只改主线过滤 → 页面「保存并重算」 → `POST /api/regime/mainline/recompute`（窄扫描，秒级，不碰 regime）。
- 改了 `regime_builder.py` 权重 → 同样走「重算」全链路，约 1–2 分钟。

前端 semafor 颜色定义：
- 状态色 / 阶段色 / 阶段文案 → `frontend/src/lib/api.ts` 的 `REGIME_STATE_COLORS`、`MARKET_PHASE_COLORS`、`MARKET_PHASE_LABELS`
- 阶段含义与应对提示 → `Regime.tsx` 的 `MARKET_PHASE_GUIDE`（第 31–38 行），需与后端判定规则同步维护
